# Category & eligibility audit - Product 2 update 1

Generated by `tools/category_audit.py` from `data/MoSJE_Scholarship_Master_V3.0.xlsx`. Full row-by-row list: `docs/category_audit.csv` (211 rows).

## What was wrong

* 297 of 525 active schemes have social category **"Not specified in verified source"** in the master.
* Eligibility Rule V3.0 treats "not specified" as *no restriction* (PASS), so a **General** student was shown schemes whose *name* says they are for Backward Classes / SC / OBC / minorities - e.g. the Karnataka Class 10 General boy (income 3.5-4.5 lakh) from the live test saw 8 schemes, 5 of which were not for him.
* The same gap existed for gender (e.g. *AICTE Pragati* = girls only) and for schemes limited to a group (disability, farmer family, PM CARES children...).

## What changed (Product 2 discovery overlay - `app/eligibility/overlay.py`)

Only where the master does **not** already restrict a condition; a master restriction is never loosened.

* **Social category restricted on 89 schemes** - 75 from the scheme name (SC, ST, OBC, BC, MBC, SEBC, SBC, VJNT, DNT, Kapu, Developing Castes, EBC/EWS, Minority, Scheduled Caste/Tribe, Dalit, Adivasi, tribal...), 14 from a single-purpose department (e.g. *Director, Developing Castes Welfare*), 0 master-vs-name conflicts.
  * Resulting sets: OBC (60), General (8), Minority (5), ST; OBC (4), OBC; General (3), ST (3), SC (3), SC; ST (2), SC; OBC (1).
  * The bot has 5 categories (SC, ST, OBC, General, Minority). DNT/NT/VJNT/SBC/Nomadic groups are mapped to **OBC**; EBC / EWS / economically backward schemes to **General**.
* **Gender restricted on 12 schemes** from the name or a curated list (e.g. AICTE Pragati, Pudhumai Penn, Nijut Moina -> Female; Tamil Pudhalvan, Nijut Babu -> Male).
* **Target groups tagged on 71 schemes**: students with disabilities (24), students of specific schools (19), children of specific workers (9), families of armed forces / police / railway staff / freedom fighters (8), other specific groups (4), PM CARES / orphan / child-care children, widows (3), BPL families (2), farmer families (1), children of school teachers (1).
  * **No group is asked in chat** (the chat is limited to 5 questions: State/UT, education level, gender, family income, social category). Disability, farmer-family and other group schemes are listed **after** the main list under "Only for specific groups - check eligibility", each showing *Only for: students with disabilities* etc. in its detail view. A Product 1 referral can still pass `facts.disability` (Yes -> main list, No -> hidden).
* **Region limit on 3 Central schemes**: Ishan Uday Special Scholarship Scheme for North Eastern Region -> Arunachal Pradesh; Assam; Manipur; Meghalaya; Mizoram; Nagaland; Sikkim; Tripura; NEC Merit Scholarship -> Arunachal Pradesh; Assam; Manipur; Meghalaya; Mizoram; Nagaland; Sikkim; Tripura; PM-USP Special Scholarship Scheme for Jammu & Kashmir and Ladakh -> Jammu and Kashmir; Ladakh.

## Education level (Update 1, feedback 5)

The chat asks: Class 1–10 (school), Class 10 passed, Class 12 passed, Graduation (UG), Post Graduation (PG), Other. Rule V3.0 only knows Pre-Matric / Post-Matric, so the master's `Education_Level_Raw` text is mapped to level codes (exact matches only) to keep PG-only schemes away from UG students, etc.:

| Level codes | Schemes |
|---|---|
| PG | 19 |
| X | 18 |
| XII; UG | 9 |
| X; XII | 3 |
| (no extra limit - Rule V3.0 stage only) | 476 |

PRE -> Pre-Matric stage; X / XII -> Post-Matric; UG / PG -> Post-Matric + Higher Education. This extends Rule V3.0's Class 10/12 derivation and should be confirmed as a product decision.

## Short display fields (Update 1, feedback 9)

Each scheme now carries `Short_Description` (≤40 chars), `Short_Eligibility` (≤50), `Short_Documents` (≤40) and `Apply_URL`, computed when the master is compiled (`app/eligibility/display.py`, cut at a word boundary with "…"). Where the master has nothing, the bot shows **"See official site"**. Source of each field over the 525 active schemes:

| Field | Source used (count) | Schemes with no source data |
|---|---|---|
| description | master `Programme_Type` (generic, e.g. "Scholarship") (480), master `Benefits` (45) | 0 |
| eligibility | built from category / income / stage / gender columns (507), master `Other_Eligibilities` (17) | 1 |
| documents | master `Documents_Required` (45) | 480 |
| url | master `Source_URL` (fallback) (302), master `Application_Portal` (223) | 0 |
| department (title line) | master `Department` | 45 |

Most common generic descriptions: "Scholarship" (236), "Educational assistance" (32), "Fee reimbursement" (22), "Merit scholarship" (20), "Educational incentive" (16). Only a minority of rows in the master have real `Benefits` / `Documents_Required` text (and the master's own benefit text is already cut at ~150 characters). Filling these columns in the master improves the cards automatically after `python tools/compile_master.py`.
